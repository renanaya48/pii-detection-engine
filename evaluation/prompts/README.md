# Well-cased prompt check

**Question:** how does the FROZEN engine behave on ordinary, correctly cased prompts, next to the informal-text
(WNUT-17) and held-out-format results? It does not change the engine and does not improve the informal-text number.

## What this set is, and is not
* **Purposive, not representative.** About two thirds of the prompts contain names and one third do not. The ratio was
  chosen by the authors, so precision and false-alarm figures depend on it.
* **AI-authored prompts from two assistant interactions; 30 were supplied by the project owner.** `author_prompts.txt`
  (158) was written by the assistant that built the engine, which knows its weak spots; `user_prompts.txt` (30) was
  generated by AI assistants and supplied by the owner. Neither part is human-written and neither is independent of the
  other (see `PROVENANCE_CORRECTION.md`, which corrects earlier wording that called them hand-written and the owner's part
  "more independent"). Hard negatives (places that are also first names, companies, products, titles) and names that are
  also common words are included on purpose, and a few famous names are present.
* **Correct casing is an assumption** about typical input. Real prompts are often lowercase and informal, which is what
  WNUT-17 represents. The names are mostly full "First Last" names (the manifest records how many are single words), which
  is easier than WNUT's mostly single-token names, so higher scores here are expected. The sets also differ in name
  length, phrasing, context and how they were created, so a gap between them does not show that casing is its cause.

## Protocol
1. Prompts are written first; the rules above are fixed before the engine is run.
2. `python -m evaluation.prompts build` parses the files into `prompts.jsonl` and writes `MANIFEST.json`: SHA-256 of every
   source file and of the data, counts, the composition note, and the id of the existing freeze (`evaluation/FREEZE.json`)
   the set is tied to. It requires the freeze to be intact.
3. `python -m evaluation.prompts run --final` scores the frozen engine ONCE. The attempt is logged in `prompts_runs.log`
   before scoring (`started`) and closed as `ok` or `failed`. It is refused if a hash or the freeze id differs from the
   manifest, or if a run is already logged (`--again` is logged too). After a run the set cannot be rebuilt.
4. Conclusions are drawn after the run, and all three result groups (this set, held-out synthetic formats, WNUT-17) are
   reported together, including the weak ones.

This directory is outside what the existing freeze covers (`evaluation/*.py` and `evaluation/data/*.jsonl`), so the original
held-out result and its freeze stay valid and unchanged.

## Entry format
Entries are separated by a line containing only `---`; lines starting with `##` are comments. `[[Name]]` marks a PERSON,
`[[EMAIL:..]]`, `[[PHONE:..]]` and `[[CREDIT_CARD:..]]` mark other PII. Titles (Dr., Mrs., Professor) stay outside the markers;
the parser rejects them inside.
